# UI-012: Tooltip and wider hit band for the attribute/title splitter

Status: **Done** (implemented and built; TDLTest passes; widened-band interactive check pending)

## Goal

Make the attribute-columns/task-title splitter discoverable and easier to grab. Dragging it
fixes the split width and silently stops the title column from following the tasklist
width; the only way back to auto-fit is an undocumented double-click. Show the available
actions while the mouse is over the splitter, with text that reflects the current mode.
The interactive band is widened beyond the drawn line so a one-pixel splitter can still
be dragged comfortably.

## Upstream starting point

- The splitter is the `CTreeListSyncer` pane splitter used by `CTDLTaskCtrlBase`
  (`Core/ToDoList/TDLTaskCtrlBase.cpp:205`, `Core/Shared/TreeListSyncer.cpp:3141`).
- Auto-fit is the `m_bAutoFitSplitter` flag (`Core/ToDoList/TDLTaskCtrlBase.cpp:241`).
  Dragging the splitter clears it (`TDLTaskCtrlBase.cpp:1904`); double-clicking it
  restores auto-fit (`TDLTaskCtrlBase.cpp:4002`).
- The attribute and title panes are not separate windows, so there is no child control to
  attach a native tooltip to. The task list already owns a tooltip for column contents,
  `m_tooltipColumns`, fed by `CTDLTaskCtrlBase::OnToolHitTest`
  (`Core/ToDoList/TDLTaskCtrlBase.cpp:373`) and filtered in
  `CTDLTaskCtrlBase::PreTranslateMessage` (`TDLTaskCtrlBase.cpp:5936`).

## What changed

Files: `Core/ToDoList/TDLTaskCtrlBase.cpp`, `Core/Shared/TreeListSyncer.h`,
`Core/Shared/TreeListSyncer.cpp`, `Core/ToDoList/ToDoList.rc`,
`Core/ToDoList/resource.h`.

- `CTDLTaskCtrlBase::OnToolHitTest` now checks the splitter first and returns a tool
  whose bounds are the splitter hit rectangle.
- Because the hit band overlaps the adjacent panes, the tool is registered against the
  window actually under the cursor (tree, list, list header or the tasklist itself).
  The rectangle is mapped into that window's client coordinates. The tool ID includes
  the window so the tooltip framework re-registers the tool when the cursor crosses from
  a pane into the gap or the other pane.
- The tip text depends on `m_bAutoFitSplitter`:
  - auto-fit on: `Drag to set a fixed width` / `Double-click to auto-fit`
  - auto-fit off: `Width is fixed` / `Double-click to auto-fit`
- Added `IDS_SPLITTER_TIP_AUTOFIT` (51953) and `IDS_SPLITTER_TIP_FIXED` (51954) so the
  text is localisable like other strings.
- No new window or message loop: it reuses the existing column-tooltip plumbing.

### Wider hit range

The visible bar can be as narrow as one pixel (`HidePaneSplitBar`). The interactive band
is now wider than the drawn bar, without changing its appearance:

- `CTreeListSyncer` gained `m_nSplitterHitPadding`, `SetSplitterHitPadding()` and
  `GetSplitterHitRect()`. `GetSplitterRect()` still returns the drawn bar, so painting
  and layout are unchanged.
- `PtInSplitter()` uses the padded rect, so the splitbar cursor and drags in the gap use
  the wider band.
- `CTDLTaskCtrlBase` sets the padding to four DPI-scaled pixels each side in its
  constructor.
- Clicks and double-clicks that land in the band but over the adjacent tree/list panes
  are intercepted in `CTreeListSyncer::ScWindowProc`:
  - `WM_SETCURSOR` shows the splitbar cursor.
  - `WM_LBUTTONDOWN` runs `DragDetect`; a real drag captures on the tasklist so the
    existing parent drag code takes over. A plain click falls through to the pane.
  - `WM_LBUTTONDBLCLK` is forwarded to the tasklist in parent coordinates, so the
    existing auto-fit handler runs.

## Behaviour

- Hovering the splitter (including a few pixels into either pane) shows the tip after
  the normal tooltip delay.
- The same band shows the horizontal-split cursor and starts a drag, even though the
  drawn line stays one pixel wide.
- The tip disappears while dragging or clicking, following the existing tooltip
  behaviour.
- The tip text updates after a double-click or drag because the tooltip is re-hit-tested
  on the next mouse move.

## Risks

- The splitter responds to hit tests only when the task list uses split panes. In
  configurations without a splitter the new branch is skipped.
- `OnToolHitTest` is shared by the tree and list task views, so both get the tip. The
  task list's own column tips are unchanged because the splitter check is a separate,
  earlier branch.
- Uses a fixed tool ID base (`0x10000`) plus the target window's handle bits, which
  cannot collide with the task/column tool IDs generated by `GetUniqueToolTipID`.
- In the widened band only, a press that turns into a drag starts a splitter drag instead
  of scrolling/dragging a task. A plain click still reaches the pane.
- `CTreeListSyncer` defaults the padding to zero, so its other users (Gantt, Workload,
  shortcuts) are unchanged unless they opt in.
